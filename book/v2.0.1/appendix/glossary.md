## 基础概念

| 术语 | 含义 |
|------|------|
| **LLM（大语言模型）** | 一个在海量文本上训练出来的"文本预测引擎"，根据上文预测下一段最可能的文字。 |
| **Token** | 模型处理文本的最小单位，大致介于"一个字"和"一个词"之间；计费和长度限制都按 token 算。 |
| **Chat API** | 以"多轮对话消息列表"为输入、返回模型回复的调用接口。 |
| **Tool Calling / Function Calling** | 模型输出"我想调用某个函数及参数"的能力，是 Agent 能"动手做事"的基础。 |
| **Prompt（提示词）** | 给模型的输入指令；`system` 角色的提示词用来给整场对话立规矩。 |
| **思维链（Thinking）** | 部分模型在给出正式回答前输出的"内心独白"，用来分步推理。 |

## 消息与内容

| 术语 | 含义 |
|------|------|
| **Msg** | AgentScope 里唯一的消息类型，带角色、内容、时间戳等。 |
| **role** | 消息角色，只有 `user`/`assistant`/`system` 三种，对齐主流 LLM API。 |
| **ContentBlock（内容块）** | 消息内容的结构化单元，共七种。 |
| **TypedDict** | "带说明书的 dict"，运行时是 dict 又有类型提示；内容块用它。 |
| **TextBlock / ThinkingBlock** | 纯文本块 / 思维链块。 |
| **ImageBlock / AudioBlock / VideoBlock** | 多模态媒体块，接受 URL 或 Base64 两种来源。 |
| **ToolUseBlock / ToolResultBlock** | 工具调用请求块 / 工具调用结果块，靠 `id` 配对。 |

## Agent 与循环

| 术语 | 含义 |
|------|------|
| **Agent（智能体）** | 以 LLM 为大脑、能调用工具、维护记忆、自主循环完成任务的程序。 |
| **ReAct** | "推理（Reason）+ 行动（Act）"的循环范式：先想，再做，看结果，再想…… |
| **ReActAgent** | AgentScope 里实现 ReAct 循环的主力 Agent 类。 |
| **Hook（钩子）** | 在方法执行前后自动触发的回调，用来插入自定义逻辑。 |
| **元类（metaclass）** | "造类的类"，AgentScope 用它在类定义时自动注入钩子。 |

## 模型与格式

| 术语 | 含义 |
|------|------|
| **Model Adapter** | 把统一的调用接口翻译成各家模型 API 具体请求的适配器。 |
| **Formatter（格式器）** | 把 `Msg` 列表翻译成某家 API 期望的请求体格式的组件。 |
| **ChatResponse** | 模型调用的结构化返回，含内容块、用量等。 |
| **流式（streaming）** | 模型一边生成一边把增量推回来，而不是等整段生成完。 |

## 工具

| 术语 | 含义 |
|------|------|
| **Toolkit** | 管理一组工具函数的容器，负责注册、分组、生成 JSON Schema、执行。 |
| **ToolResponse** | 工具执行的结构化返回，支持多模态。 |
| **JSON Schema** | 描述一个函数"接什么参数"的标准格式，模型据此知道怎么调工具。 |
| **MCP（Model Context Protocol）** | 让模型连接外部工具/数据源的通用协议；AgentScope 既能当 MCP 客户端也能把工具暴露成 MCP 服务。 |

## 记忆与知识

| 术语 | 含义 |
|------|------|
| **Working Memory（工作记忆）** | Agent 在一次对话里记住的上下文（消息历史）。 |
| **InMemoryMemory** | 把工作记忆存在进程内存里的默认实现。 |
| **Long-term Memory（长期记忆）** | 跨会话持久化、可检索的记忆，如基于 Mem0 的实现。 |
| **RAG（检索增强生成）** | 先从知识库检索相关片段，再喂给模型作答的技术。 |
| **Embedding（向量嵌入）** | 把文本映射成向量，以便做相似度检索。 |

## 编排与通信

| 术语 | 含义 |
|------|------|
| **Pipeline（流水线）** | 把多个 Agent 按某种结构串起来的编排方式（顺序、扇出等）。 |
| **MsgHub** | 一个"发布-订阅"作用域，作用域内的 Agent 互相喊话会被自动广播。 |
| **SequentialPipeline / FanoutPipeline** | 顺序流水线（一个接一个）/ 扇出流水线（同时发给多个）。 |

## 可观测与会话

| 术语 | 含义 |
|------|------|
| **Session（会话）** | 一次有状态的交互，框架自动管理其中的状态。 |
| **Tracing（追踪）** | 基于 OpenTelemetry 的调用链追踪，可对接 Phoenix、Langfuse 等平台。 |
| **StateModule** | 可序列化、支持状态自动管理的模块基类。 |

## 2.0.1 新增：团队与生产

| 术语 | 含义 |
|------|------|
| **Agent Team（智能体团队）** | 把多个 Agent 组织成可分工、可寻址、可服务化的协作团队。 |
| **app 模块** | 用 FastAPI 把 Agent 能力封装成可 HTTP 调用、可扩展、可持久化的服务。 |
| **message_bus（消息总线）** | 团队成员间投递消息的通道，本地或 Redis 两种实现。 |
| **Workspace（工作空间）** | 给 Agent 的一块可读写、可隔离的工作区（本地 / Docker / 云沙箱 E2B）。 |
| **Skill（技能）** | 一组工具+提示打包成的可加载"技能包"。 |
| **Permission（权限）** | 工具调用前的安全判定层，按规则决定允许/拒绝/需确认。 |
| **Credential（凭证）** | 统一管理各家 provider 的 API key 等访问凭证。 |
| **Event（事件）** | 服务化后向前端流式推送的执行过程事件（文本增量、模型调用起止等）。 |
| **Middleware（中间件）** | 套在 Agent 调用链外的"洋葱模型"层，可叠加追踪、TTS 等横切能力。 |
